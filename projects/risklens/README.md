# RiskLens — Explainable Transaction Risk ML Dashboard

**Stage:** runnable full-stack research prototype, **not deployed**. Uses ONLY fictional, synthetic transaction data.

An end-to-end machine-learning application with a deterministic dataset generator, baseline model comparison, gradient-boosted inference service, risk assessment dashboard, validation metrics, and permutation-based **global** feature importance.

## Engineering architecture

```text
React / Vite ──REST──► FastAPI ──► Scikit-learn model pipeline
                                      │
                      Seeded synthetic transaction generator
                                      │
                          Stratified train/validation split
                                      │
                          Logistic regression baseline
                                      │
                            Gradient-boosted model
                                      │
                Average precision · ROC AUC · Confusion matrix
```

## What is actually implemented

- Reproducible 6,000-record dataset using seeded synthetic feature distributions and injected label logic.
- Imbalanced binary classification, gradient-boosted estimator, logistic regression comparison.
- Validation: average precision, ROC AUC, and confusion matrix.
- Risk scoring endpoint, input constraints, simple review threshold, global permutation feature importance.
- Responsive React interface and API tests.

### Run locally

Python 3.10+ and Node.js 20+.

```bash
# From project root
python -m venv .venv
# macOS/Linux: source .venv/bin/activate
# Windows: .venv\Scripts\activate
pip install -r backend/requirements-dev.txt
uvicorn backend.app:app --reload --port 8000
```

Second terminal:

```bash
cd frontend
npm install
npm run dev
```

UI: http://localhost:5173 · API docs: http://localhost:8000/docs.

Run automated tests and evaluation:

```bash
python -m pytest backend/tests -q
python -m backend.evaluate
```

| Endpoint | Operation |
| --- | --- |
| `GET /api/health` | Health check |
| `GET /api/metrics` | Synthetic validation metrics and global importance |


## Data and model limitations

**No real banking data is used.** Features, distributions, and labels are generated by hand-crafted rules, so performance cannot be generalized to real financial transactions. Scores are model outputs, **not calibrated probabilities of actual fraud**. The demo review threshold is selected using the same validation subset used for reported metrics, so those statistics can be optimistic. Feature importance is global permutation importance, **not SHAP or a per-transaction explanation**.

This app is an educational portfolio prototype: **never use it for fraud investigations, transaction blocking, customer decisions, or real compliance risk scoring.** There is no production security, drift monitoring, audit store, bias audit, or calibration.
